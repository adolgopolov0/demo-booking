## Ключевые промпты

- «составь анализ кода app/Http/Controllers/BookingController.php на предмет соответствию правил ларавел»
- «составить план ревью в файле REVIEW.md в корне на основе анализа краткие выкладки»
- Функционал и тест-кейсы контроллера. Создать `TESTCASES.md` в корне. Только методы `index`, `store`, `destroy`, `today`. Кейсы нумеруются внутри метода одной фразой: кто действует, что делает, какой результат. Кейсов на доработки нет: шаг 15 минут, длительность до 4 часов, отмена только автором, пустые поля, стык интервалов, подмена `user_id`. Данные из сидера и примера запроса в `README.md`. Контроллер не менять. Новые feature-тесты не писать. Существующий `tests/Feature/BookingIndexTest.php` не трогать: он проверяет `index` через фабрики, без токенов Анны и Бориса.
- Рефакторинг по ревью и тестам. Слои: `BookingController` вызывает Form Request и `BookingService`, сервис вызывает `BookingRepository`, реализация `EloquentBookingRepository`. Контроллер оставляет действия `index`, `store`, `destroy`, `today`: разбор запроса, код ответа, вызов сервиса, return type. Сервис держит правила: владелец из текущего пользователя, пояс офиса, рабочий час 9–20, пересечение, лог `Booking created`. Репозиторий только читает и пишет. В `AppServiceProvider` связывается `BookingRepository::class` с `EloquentBookingRepository::class`. Контроллер получает сервис через конструктор, сервис получает репозиторий. Отдельный Form Request на список, создание, удаление и брони на сегодня. В `store` проверяются `room_id`, `title`, `starts_at`, `ends_at`. `user_id` из тела не используется как владелец. «Комната занята» и «Нерабочее время» отдаёт сервис как `{"error":"..."}` и 422. `store`: ISO с любым смещением переводится в пояс офиса. Арбат `10:00+03:00` читается как `10:00` `Europe/Moscow`. Обь `10:00+03:00`–`11:00+03:00` читается как `2026-11-02T14:00:00+07:00` и `15:00:00+07:00`. Час начала в поясе офиса: `08:00+03:00` и `20:00+03:00` на Арбате дают 422 «Нерабочее время». Пересечение той же комнаты — 422 «Комната занята», проверка и запись в одной транзакции с блокировкой, SQL без подстановки строк. `destroy`: implicit binding, тот же URL. Нет записи — 404. Чужая бронь — 403, запись остаётся. Своя — 204 и пропадает из своего `index`. `index`: только свои брони, `orderByDesc('starts_at')`, страница 20. `today`: брони комнаты за сегодня, поля `time` и `author`, пользователь загружается вместе с бронями. Нет комнаты — 404. Без токена `AuthenticationException` для `api/*` рендерится как 403, без редиректа на `login`. Проверка файлами `BookingAuthTest`, `BookingIndexTest`, `BookingStoreTest`, `BookingDestroyTest`, `BookingTodayTest`. В `BookingIndexTest` ожидание 401 заменяется на 403, остальные тесты не меняются.
